# Carrel MCP 修正與 Codex 重測 — 2026-10-01

**已修正並部署前次評估的所有介面與預演問題。** 相同 7 段 prompt 共使用 **21 次工具呼叫**，前次為 48 次，減少 **56%**。非預期失敗由 6 次降至 0；唯一拒絕是刻意要求超額資源的測試。

## 實作與驗證

- 所有成員 mutation 的成功預演統一回傳 `quota_before / delta / quota_after`，並帶剩餘額度；涵蓋網路、port、domain、快照的增刪及刪機連帶釋放資源。管理員修改額度另回傳 `limit_delta`。
- 缺 SSH 公鑰仍會檢查規格、配額及容量，回報 `requirements`、`ready_to_apply=false`。實際建立仍拒絕缺 key；提供的無效 key 也會被拒絕。
- 新資源預演為 `planned`、`reserved=false`、`resource_changes=false`，省略未配置的 VMID、IP、port、SSH 命令及建立時間。稽核紀錄仍會寫入；首次使用的資格租戶仍依既有規則自動註冊。
- 新增唯讀 `deployment_plan`，以名稱引用新／既有 VM 與私網，合計配額、主機容量與 NIC 數量。兩台各 6 vCPU 對 8 vCPU 租戶會拒絕；兩台 2 vCPU 加私網及 NIC 可完整預演，不寫入資源。
- 新增 `capacity_get`，使用與 admission 相同的計算，分開呈現實體用量、可配置量及超配政策。計入 local-lvm 所有虛擬磁碟與未完成配置的保留量；不回傳其他租戶名稱或 VMID。
- `whoami` 一次回報個人／專案配額、預設租戶及能力；`catalog_get` 合併映像與規格。舊 `images_list`／`sizes_list` 仍可呼叫，但不再出現在 discovery。
- 隱藏未支援的 `images_gb` 配額及申請選項，保留資料庫既有值；明確標示 MiB／GiB、GPU 配置不支援及硬體庫存未知。MCP resource discovery 正常回覆空清單。

自動化驗證：**59 tests passed**，Ruff、Python 編譯及 `git diff --check` 通過。測試包含預演不修改 tenants／objects、配額正負方向與管理員 limit 預演、跨租戶拒絕、聚合主機容量、保留量不重複計算、MCP schema／discovery 與既有 OAuth 安全檢查。

Codex 重測的控制程式 commit：`4b8ed4c`；之後另以 `271640a` 修正生命週期實測發現的快照還原狀態。node adapter 更新磁碟 inventory 與 rollback 狀態回傳。最終線上模組及 adapter 的 SHA-256 與原始碼一致；部署保留回復副本，服務及公開 health check 正常。

所有 21 次呼叫皆為查詢或預演，沒有 shell 命令、資源 mutation、SSH key 寫入或配額申請。預演成功後不再重查列表證明「沒有建立」。模型清楚說明尚未驗證客體開機、套件及連通性，沒有把規劃結果當成執行結果。

每個情境只有一次重測，不能推論跨模型成功率。耗時包含 CLI 啟動、網路及模型推理；部分情境仍較慢，這次可確定的改善是工具往返及結果完整性。部分模型仍先查 `capacity_get` 再預演，屬可省略的額外查詢，未造成錯誤。原有 provider model-list 解碼訊息仍出現在 CLI stderr，沒有使 session 失敗；它不是 Carrel server 問題。

## 真實 VM 生命週期

Codex 的唯讀比較結束後，另外在 `zyx1121` 建立一台全新的拋棄式 Ubuntu 24.04 VM：`carrel-eval-1001`，1 vCPU、1 GiB RAM、12 GiB disk，使用臨時 owner key。未操作既有工作負載。

- 公網 SSH 登入成功；等待 cloud-init 完成後，nginx 服務及 guest HTTP 回應正常。
- 建立獨立私網並掛 NIC；guest 可見網卡，MTU 為 1450，能設定私有 IP。這不是兩台 VM 之間的連通性測試。
- 額外 TCP port 的 HTTP 與獨立子網域 HTTPS 皆取得 nginx 頁面，HTTPS 使用正常憑證驗證。
- 建立 disk snapshot 後新增測試檔；還原後檔案消失，nginx、SSH、HTTPS 恢復正常。
- 實測發現原先 rollback 回報成功卻仍保留 `ready` 狀態，即使 hypervisor 已停機。修正並部署後再次還原，回傳與資料庫均為 `stopped`，並提供 `machine_power start`；啟動後再次驗證檔案復原。
- 建立／刪除網路、port、domain、snapshot，以及機器刪除的預演配額均與實際操作結果一致。
- 測試 VM、磁碟、私網、domain、公開 port、snapshot 已清除，臨時私鑰已銷毀；個人及專案的配置用量恢復為 0。正常稽核與可重用的租戶 TLS 憑證快取保留。

這次只驗證 Ubuntu VM；沒有重跑 CT、跨租戶 peering 或多節點測試。快照是磁碟還原，不能視為記憶體狀態或不中斷服務的還原。
